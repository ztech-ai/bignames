# 采编与自动化操作手册

记录：OpenAI Codex（AI助手） · 2026-11-15；事实截止2026-11-13

目标是把重复动作交给程序，把研究、取舍和语言判断留给编辑。网站始终是静态文件；下面的Node与Python脚本只在开发或交付阶段运行，不引入数据库、服务端应用或访问者端AI调用。

运行环境依照 `package.json` 的Node版本要求，另需Python 3。首次开发安装依赖使用 `npm ci`；该安装可能联网，后续工作流验证使用已经安装的本地依赖。

## 输入与输出

| 路径 | 内容与用途 |
| --- | --- |
| `data/collections/contemporary-1000.json` | 本轮1000位新增候选、评级与筛选信息 |
| `data/research/evidence/<id>.json` | 来源事实、版本与图片资料，待审；不直接发布 |
| `data/research/drafts/<id>.json` | 共享事实及八语模板视图，可能有缺失和回退；不直接发布 |
| `data/research/editorial/<id>.json` | 已进入正式档案的新人物采编记录；不能据此推定人工审校 |
| `data/people/<id>.json` | 正式事实与中文底本，一人一份；稳定ID是跨语言关联依据 |
| `data/images/<id>.json` | 正式肖像的来源、作者、许可与本地资源记录 |
| `data/i18n/<语言>/people/<id>.json` | 正式译文与严格底本版本哈希 |
| `data/i18n/snapshots/` | 增量翻译使用的按内容哈希索引的底本快照 |
| `dist/` | 由模板生成的静态网站；不直接在这里编辑人物内容 |

目前425份正式档案提供8语言页面，千人集合401人完成、599人待完整采编；1000份证据/事实草稿是独立研究层。本批按最高剩余四星及领域候选容量选择100人，325份旧基础档案不变。提交和Pages发布已获用户授权，由main分支Actions执行。奥特加既有姓名占位例外保留，本批没有新增占位。

## 常用流程

### 1. 先看短状态，选取小批次

```sh
npm run workflow:status
npm run content:plan

# 例如：先处理科技领域的8位待编人物
npm run content:plan -- --domain technology --limit 8

# 只导出一个人的有限事实与事件；完整原始资料仍保留
npm run content:brief -- --person bill-gates --max-events 12 --max-facts 20 --out /tmp/bill-gates-brief.json

# 从工作包中取稳定ID，按需读取完整事实；事件使用 --event EVENT_ID
npm run content:detail -- --person bill-gates --fact fact-36ba99b04e49f7f021d5
```

状态命令报告正式档案、语言版本及研究文件存在情况，不读取整套草稿来向AI倾倒数十MB资料，也不据此认证所有来源事实。计划命令默认返回最多12位待编人物，排除已有完整档案；`--json` 可供其他程序读取。

为选定人物生成简短中英工作包，再按事实或事件ID取得必要的详细证据。不指定输出位置时写入 `.qa/packets/<id>.json`；命令仅打印大小摘要，避免整份输入自动进入会话。工作包会列出裁减内容的数量、稳定ID及完整资料位置；底层证据与草稿版本不匹配时停止。限额仅影响给AI或编辑的输入量，不会修改证据，不会删减正式简历，也不会自动发布。

编辑应先检查身份、存活状态、重大履历、信息缺口和日期精度。事实按属性取样，年表保留首尾并按时间间隔取样，采样不是重要性判断。发布前必须对照遗漏清单查看完整资料并决定是否纳入；必要时读取原始来源，不能仅凭短包就宣称履历完整。

### 2. 仅在需要更新来源时采集

```sh
# 会访问外网，支持缓存和断点续采；不是每次构建的必需步骤
npm run research:fetch

# 从本地证据重建八语事实视图，不调用模型
npm run research:drafts
```

缓存和结构化草稿避免让AI重复抄录同一事实。来源访问日期与内容版本仍须核对。机器身份检查只排除一部分同名或非人物实体错误；确认在世、重要事件取舍、近期来源补充和交叉验证仍由编辑完成。

当前证据与草稿保留 `needs-review` / `publicationReady: false` 等状态；程序不会批量晋升为正式人物。抓到一张带许可的图片也不等于完成肖像核验。

### 3. 形成正式档案，再用同一套模板出页

依据已核对来源编写 `data/people/<id>.json`，准备图片元数据和各语言文字，并记录采编范围。至少6条有来源的倒序事件、2项代表成果、2项来源和8语言完整正文；最低数量不能代替覆盖完整性与来源质量。

- 保留已有 `facts`、`highlights`、`timeline` 的稳定ID；插入条目使用新ID，排序变化不重新编号。
- 日期、来源、分类ID、星级和生卒状态只修改共享底本。中文文字与各语言译文分别维护，评级理由随文字参与增量翻译。
- `death: null` 必须基于在世核对；有效死亡日期触发列表、详情和打印的黑白规则。缺失死亡信息不能当成已核实在世。
- 照片核对本人、清晰度、裁切、作者和许可；在世保留原始彩色，已故通过统一样式显示黑白，不破坏源图片。
- 正文用简短原创表述，来源通过链接支持关键事件；保留覆盖说明，不把访问日期当作年表覆盖终点。

同一模板生成全部人物与语言页面。日常增加人物不需要AI逐页写HTML；只有确实改变交互或设计时才修改模板、样式与前端脚本。

### 4. 更新既有底本时只处理变更译文

先保存已经通过校验的当前底本，再编辑中文或共享事实。快照必须在旧版本仍可验证时建立；编辑之后无法拿当前内容伪装成旧底本。

```sh
# 编辑前：为当前有效译文建立可追溯底本
npm run i18n:snapshot

# 在编辑器中修改正式底本，然后为受影响的人物与语言导出增量
npm run i18n:delta:export -- --locale en --person sam-altman --out /tmp/sam-altman-en-delta.json

# 审阅并填写工作包后再导入
npm run i18n:delta:import -- --locale en --person sam-altman --file /tmp/sam-altman-en-delta.json
```

`snapshot` 不指定范围时检查所有已启用目标语言的人物与界面；也可加 `--locale en --person sam-altman` 限定范围。界面增量使用 `--ui`，可与一个人物共同导出。导出与导入都必须显式指定相同语言和人物/界面范围。

工作包包含增加、改写或删除的字段、旧源文、现有译文和必要上下文。只需改译受影响字段，但所有列出的变更都必须明确审阅；删除条目也不能悄悄忽略。具体填写：

- `entries[].units[]`：修改需翻译的 `target`，逐项设置 `reviewed: true`；删除项保持 `target: null`。不要修改 `key`、`operation`、源文、哈希或其他只读上下文。
- `reviewer`：实际由AI审阅时填写 `{"kind":"ai","name":"OpenAI Codex（AI助手）"}`；实际人类审阅时使用 `human` 和真实身份。这是自报记录，不是身份认证。
- `entries[].sharedFacts.required: true`：查看所列非文字变更与受影响的现有译文，确认后设置该条目的 `sharedFacts.reviewed: true`。若日期或事实变更要求改写原来未变化的译文，应先修订相应中文底本文字并重新导出，使语义改动进入翻译流程。

日期、生卒、来源等非文字变化不会因为“没有文字字段变化”而自动通过。完整底本哈希仍严格生效；增量只缩小编辑工作量，没有放宽版本检查。

填写审阅标志是事实声明，不是绕过核对的按钮。导入保留未变化的译文，在人物译文或界面元数据中保存 `deltaReview` 审阅记录，并保存新底本快照；无变化包不会修改译文。导入不会调用模型、自动翻译、自动启用新语言或发布网站。

导入依赖可信旧快照与当前底本；底本、旧快照、工作包或现有目标译文出现不一致时应重新导出处理，不能手工改哈希“消除报错”。缺少旧快照时，使用原有的完整导出/导入流程重新审阅；不要把新底本保存为虚构旧版本。

新增语言和首次翻译仍采用[完整多语言流程](TRANSLATION-CONTRACT.md)。增量模式是既有内容更新的补充，不能省略初次完整翻译。

### 5. 验证、查看页面、交付

```sh
# 日常正式验证：构建、数据与链接检查、JS测试、Python测试
npm run workflow:verify

# 编辑过程的快速反馈：仅构建和检查，不能冒充完整测试
npm run workflow:verify -- --quick

# 交付前重新完整验证，然后生成静态包、源码包和校验信息
npm run workflow:package
```

完整验证按构建、检查、JavaScript测试、Python测试依次执行，失败即停。成功后记录 `.qa/workflow-verification.json`，但交付命令不会用旧报告免除本次验证。快速模式明确标记为 `quick`；交付命令不提供跳过完整验证的选项。

工作流不联网、不调用模型、不部署。验证能发现结构、翻译键与版本、链接、数据规则和代码行为问题；不能证明所有人物事实正确，也不能证明所有语言自然流畅。

页面有模板、样式、字体或较大篇幅变化时，另行用实际浏览器检查首页筛选、长简历、窄屏、阿拉伯语RTL、打印以及在世/已故照片。当前命令不会自动完成浏览器目视验收，交付清单如实记录该项未由命令执行。不能用静态检查结果冒充已看过页面。

默认交付输出到项目父目录，可用 `npm run workflow:package -- --out /项目外/交付目录` 指定位置；`workflow:status`、`workflow:verify`、`workflow:package` 均可加 `--json` 输出机器可读摘要：

- `big-names-static.zip`：可独立托管的静态文件。
- `big-names-source.zip`：可重新构建的源码、正式资料、研究记录和必要图片。
- `big-names-SHA256SUMS.txt`：ZIP文件的SHA-256校验和。
- `big-names-manifest.json`：输入与静态输出指纹、实际验证项、限制和构建记录。

ZIP按固定顺序、固定时间戳和权限生成；相同输入与相同Python压缩环境可得到相同ZIP字节。清单包含实际生成时间，不承诺其每次字节相同。源码包排除Git历史、依赖目录、构建目录、原始下载缓存、环境变量文件与临时文件；第三方资料和照片仍保留其署名与许可。交付只生成文件，不推送仓库，也不处理域名或Pages。

## 失败时怎么处理

| 现象 | 处理方法 |
| --- | --- |
| 快照不存在或源版本不匹配 | 回到可核对版本或采用完整翻译流程；不要改哈希伪装已审阅 |
| 导出后底本或译文又改过 | 重新导出并合并真实改动，避免旧包覆盖新内容 |
| 有非文字事实变更未确认 | 查阅日期、来源或生卒变化，确认是否影响语义后再逐项记录 |
| 模板事实有缺失、标签回退、身份阻断 | 补来源与编辑判断；保留待审状态，不用空壳简历填数 |
| 构建或测试失败 | 修复对应输入或代码后重跑；交付时必须通过完整验证 |
| 目视检查无法进行 | 记录未执行及实际原因；不写“视觉验收通过” |

## 成本与质量怎么衡量

优先记录每批处理人数、导出字段数、字符/字节量、实际修订字段数和校验结果。AI上下文优先包含相关人物的变化与证据，不重复输入全部1000人资料或完整生成网站。字符和字节不等于精确计费Token，不能据此承诺固定费用降幅。

减少的是重复读取、机械转写、逐页HTML和无变化译文处理；保留的是来源核对、重大事件覆盖、照片准确性、语义审阅和页面检查。尚未提供可直接发布的自动机器翻译流程、批量自动发布、所有语种人工审校或完整事实审计系统。公共机翻试运行因限流及实质语义错误停止，本批六种外语由AI逐字段复核/补译，未审机器稿禁止进入正式构建。

分工、署名与审阅限制见[署名与自动化说明](AUTHORSHIP-AND-AUTOMATION.md)。

## 本批新增的复核保存与批次核验

`scripts/reviewed-translation.mjs`导出的`save(id, locale, strings)`用于保存已完成语义审阅的完整六语译文。它不翻译、不调用模型、不联网；先校验中文底本和英文参考版本、完整字段，再以原子写入保存译文和实际审阅者声明。审阅记录是自报，不是人员身份或母语资格认证。允许复用未变化且已审的字符串，只修订实际受影响的字段，不需重新生成整页HTML。

这类译文同时保留中文sourceHash与英文文字参考哈希。中文或英文参考发生变化后，先复核受影响事实/文字，再用保存器写入；不得直接改哈希消除错误。既有完整/增量翻译命令继续用于提取差异，带有此类英文依赖的六语文件还须完成英文参考变更核对。

交付批次还可运行：

```sh
node scripts/check-batch.mjs --batch data/collections/influence-100c-2026-11.json --report data/research/influence-100c-report.json
```

它检查基线人物SHA-256未变、评级对象原样继承、领域均衡、资料最低覆盖、译文版本/审阅字段、肖像与已审字节哈希，并生成简短机器报告。它不能认证每条事实、照片身份或语言自然度。旧批次清单与报告是交付时点的历史记录，不要求在后续新增或获准更新存量后继续满足旧总人数。

## 最早24人获准更新后的基线

用户已明确要求“先更新最早的24人履历”，原冻结约束因此进入独立复核阶段。`data/research/baseline.json`仍保留原始内容，不覆盖历史。`legacy-refresh-2026.json`记录用户授权范围、原Git blob、完成审阅后的新blob及其他171份基础资料的SHA-256。检查程序只接受完整、锚定原基线且精确覆盖这24人的完成记录；未完成或不匹配仍拒绝构建。履历更新不自动追加影响力评级。

本轮使用原有增量导出/审阅/导入，23份底本有变更；孔子复核后无实质改动。994个新增/变化的外语字段经AI核义，6,440个未变化译文原样复用。日期/引用等共享事实的变动同样要求审阅，不用直接改hash来绕过校验。

## 随素材提供完整许可

图片仍必须保存真实的`license`、`licenseUrl`、`credit`和`sourceUrl`。需要随作品附完整文本时，把文件放入`public/assets/licenses/`，并在图片元数据添加`licenseText: "assets/licenses/GFDL-1.2.txt"`。生成器在八语人物和许可页使用可解析的本地链接；检查器拒绝越界路径并确认文件存在。该字段不改变素材本身的许可；不能据此声称任意图片可用。

## 自动生成交付统计与署名表

当一批人物全部冻结后执行：

```sh
npm run content:report -- --batch data/collections/influence-100c-2026-11.json
```

脚本先运行批次核验；失败不更新输出。通过后写入批次报告、`edition-report.json`、本批CSV和`docs/IMAGE-CREDITS.md`。完整档案、来源和研究草稿仍分开计数；程序不把计数或自报AI审阅记录当成事实认证，不修改人物、评级或译文。该步骤在完整构建/测试/打包之前完成。

来源对出生年份有分歧时，用`birth:null`+有序`birthYears`保存备选；在基础资料正文说明来源分歧。网站展示全部备选年份，排序按最早可能年，搜索引擎JSON-LD不输出确定出生日期。不要为通过格式检查而编造年份。

## 高星级领域容量不足时

批次设置`allocation: "capacity-balanced-highest-tier"`，记录覆盖全部领域的`domainPriority`、同级剩余`domainCapacities`及有具体理由的`selectionExclusions`。`batch-allocation.mjs`逐轮分配，少量领域到容量即停止，其余名额继续给有容量的同星级领域。`check-batch`重算容量和配额，拒绝跳过更高星级、无理由排除、领域遗漏、未审姓名占位或与基础数据不同的主领域。

程序只能约束已记录的选择，不独立认证每个待编候选仍在世或已获肖像授权。出版前仍需逐人研究、照片与完整八语语义审阅；有新障碍时保留理由并由整合者更新名单/容量，不能靠临时降星填数。
