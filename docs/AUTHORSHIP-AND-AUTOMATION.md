截至本次记录，网站有 **195份正式人物档案、每份8种语言，共1,560份人物HTML**，连同辅助页面共1,600份HTML。初始24份之外，新增千人集合已有171位进入正式档案（首批24位、五星批47位、本批四星100位）。本批保留之前95份人物基础JSON，没有修改评级来凑人数。

实际检索截止日为2026-11-13。来源访问时间、来源内容版本和人物年表覆盖时间分别记录，不能因为今天取得一份网页，就宣称人物履历已完整更新到今天。部署保持暂停；本次自动化只处理本地数据、静态构建、验证和交付文件。

## AI与程序各自做什么

| 环节 | 需要编辑判断的工作 | 已程序化的工作 |
| --- | --- | --- |
| 人物筛选与评级 | AI辅助选择有公共影响力的人，解释领域覆盖、星级和理由；可由人工复核调整 | 合并候选、去重、固定1000人名单、应用已确认的排除项、检查评级字段 |
| 资料研究 | AI查阅来源，辨认同名者，交叉核对事实，判断哪些履历重要、是否仍有效 | 通过公开接口取得并缓存来源，记录版本、声明ID和日期精度；检查实体是否为人物 |
| 正式简历 | AI依据证据重新组织摘要、代表成果与倒序年表，保留争议和覆盖范围；可由人工编辑 | 输出待办、压缩工作包、生成事实草稿、检查必需字段和引用关系 |
| 多语言 | AI翻译或修订语义、姓名、语气和评级理由；可由相应语言编辑审校 | 提取文字、保存底本快照、导出变更项、校验审阅确认、导入译文、拒绝过期或冲突工作包 |
| 照片 | AI查看图片，核对本人、裁切和授权资料；可由人工复核 | 保存来源与许可，复用一张主图；依据唯一 `death` 字段统一彩色或黑白 |
| 页面 | AI设计信息层次、响应式样式与模板，并在修改时判断呈现效果 | 一套模板生成全部人物与语言页面、搜索数据、链接和站点地图，统一转义文字 |
| 验证与交付 | AI分析失败、修复代码；人工或可用的浏览器工具检查实际观感 | 检查结构、翻译版本、链接与数据约束，运行测试，生成ZIP、校验和与交付清单 |

这里“AI处理”包括AI工具调用与AI同伴复核，不代表每个字都由模型独立生成。程序最初也由AI编写和修订，但程序一旦保存，常规执行不需要再次让模型生成同样的页面或逐条抄写资料。

### 当前AI工作的审阅边界

本轮正式文案、翻译、影响力判断和编辑核对由AI辅助完成；现有采编记录中的“reviewed”“editorial-review-complete”等状态不应被解释为人类编辑签字或八种语言母语者全面审校。AI同伴复核仍是AI复核。未实际发生的人工审阅，不补写姓名、签名或审校结论。

新增的增量译文导入要求显式记录审阅者类型和身份。`ai` 与 `human` 必须如实填写；工具只能验证记录格式与确认项，无法证明填写者身份，也无法判断译文一定正确。既有采编记录不会因为增加本说明而自动获得新的人工审核记录。

程序能发现字段缺失、版本过期和部分不一致，不能代替以下判断：

- 来源是否足够可靠，是否把旧职位误写成现任，是否遗漏重大转折。
- Wikidata `P31=Q5` 只能辅助确认实体属于“人”，不能独立证明是目标人物，也不能证明仍在世；没有死亡日期也不等于已核实在世。
- 模板生成的八语事实视图包含标签回退和待审项，不等于完整翻译。正文自然度、敏感措辞和事实含义仍需审阅。
- 照片文件能打开且带有许可字段，不等于已核实肖像是本人或该使用符合所有许可条件。
- 静态HTML、DOM和链接检查通过，不等于浏览器中的移动端、阿拉伯语排版与打印效果已完成目视验收。

## 本次固化的节约方式

1. **事实只存一处。** 日期、生卒状态、来源、分类与图片不在八种语言中重复维护；文字通过稳定条目ID对应。评级星级共享，评级理由进入各语言文字流程。
2. **先选择，再读取。** 内容命令先给出短待办，再按人物导出有限事实与事件；明确列出省略数量、ID及完整来源路径。需要核对时再按ID读取完整条目，不将省略当成“不存在”。
3. **只处理实际改动。** 编辑前保存受校验的底本快照。编辑后只导出增加、修改、删除的文字及必要上下文；日期、来源等非文字变化单独要求审阅，避免靠减少文本绕过事实核对。
4. **模板批量渲染。** 不让AI为每个人、每种语言再写一份HTML。修改模板后统一构建，保留简历式布局、语言切换、来源链接与照片规则。
5. **一次检查，一次交付。** 固化失败即停的检查顺序，默认输出简短摘要；需要定位错误时查看详细结果。交付命令重新完整验证并记录文件校验和。

`content`、增量译文、`workflow` 和静态构建命令本身不调用模型。公开资料抓取命令需要网络，但也不调用模型。程序执行耗费本地CPU、磁盘与必要的网络资源；若由AI操作，命令上下文和工具输出仍会消耗会话Token，因此短输出也有意义。

没有给出固定节省百分比。字符数、UTF-8字节数、变更字段数是可核对的工作量指标，**不是模型供应商精确计费的Token数**。实际节省取决于改动规模、语言、模型和人工/AI流程，不能把整个网站的HTML体积直接折算成AI费用。

## 保留的质量门槛

正式档案至少具备6条有来源的倒序事件、2项代表成果、2项来源、准确且有许可记录的主体照片，以及完整的8语言文字。照片仅允许明确记录的例外：用户已确认奥特加先用姓名占位，页面标注肖像待补；元数据不冒充有照片或授权。数量是最低结构门槛，不是充分证据：不能为了凑数编造事件、把教育结束时间当成毕业、把无结束时间的职位当成现任、或把未来计划写成完成成果。

影响力评级依据[五星方法](../data/collections/influence-method.json)，保存理由、日期、方法与状态；它是可修订的编辑判断，不是道德评价或人的价值排名。减少Token不会降低收录门槛、删掉关键争议、隐藏缺失译文或自动提高星级。

## 来源、权利与后续记录

程序、原创整理文字和第三方研究材料分别处理。Wikidata、Wikipedia摘录与每张Commons图片各有适用许可；代码许可证不覆盖第三方内容。按[研究材料许可说明](../data/research/NOTICE.md)保留原作者、来源版本和许可链接，正式图片保留网站署名。发布者仍需按实际使用场景履行相应许可条件。

已落地的是现有逐人采编记录、增量译文审阅记录的写入机制、自动验证与交付清单。统一记录所有研究、写作、事实复核、人工签字和页面目视验收的完整审计系统尚未实现。后续如扩展，应记录实际操作者及 `ai` / `human` / `program` 类型、动作、日期、来源版本、结果和明确限制；不回填虚构的人工审阅。
